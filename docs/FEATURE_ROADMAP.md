# 預測特徵累積狀態與驗證清單

最後更新：2026-07-25

這份文件記錄各資料來源要成為預測特徵還缺什麼、以及每一項該怎麼驗收。
目的是避免兩件事：把還沒準備好的資料接進模型，以及把已經準備好的資料
一直晾著。

**目前結論：沒有任何外部資料源可以進特徵欄位。** 不是資料不好，是
surge 樣本太少（160~184 天裡只有 18~21 次），任何特徵的增量價值都測不出來。

---

## 一、驗收門檻

新特徵要通過三關才能進模型。跑 `scripts/analysis/audit_feature_sources.py`
一次檢查全部。

| 關卡 | 門檻 | 為什麼 |
|---|---|---|
| 覆蓋率 | 來源歷史需蓋住訓練窗口 | 只有 6 個月歷史的來源放進跨 10 年的模型，99% 的列是「沒爬到的零」，模型學到的是「有資料 = 2026 年」 |
| 非零密度 | 非零天數 ≥ 15% | 一年出現 5 次的類別，AUC 再高也是雜訊 |
| 增量價值 | bootstrap 95% 區間不跨 0 | 見下方 |

### 增量價值這關最容易誤判

單一特徵的樣本內 AUC 會嚴重高估。`news_relevant` 樣本內 AUC 0.625 看起來可用，
控制序列特徵後掉到 0.543。

而且**點估計本身也不可信**。同一組新聞特徵：

```
n_splits=3   +0.045  值得加入
n_splits=5   +0.093  值得加入
n_splits=6   -0.038  不要加      <- 翻面
n_splits=10  -0.011  不要加
```

bootstrap 95% 區間 `[-0.153, +0.199]`、差異為正的比例 52% —— 等同擲銅板。
根因是每折只有 3~4 個正樣本，單折 AUC 在 0.32~0.85 之間亂跳。

**所以只看 bootstrap 區間，跨 0 一律當「無法判定」，不給假綠燈。**

## 六、軍艦通過分類問題（2026-07 稽核）

### 6.1 日本水域過度標記

2026-01-05 起四個海峽欄位全部被填 0/1，其中 **13 筆地理上不可能**：

```
2026-02-16  與那國(24.4°N) + 對馬(34.4°N)   艦型=斯捷雷古什奇級護衛艦、杜布納級補給艦
2026-03-10  與那國 + 對馬                    艦型=守護級護衛艦、巴爾克級遠洋拖船
（共 13 筆，艦型多為俄羅斯艦艇）
```

相距約 1,400 公里，同一批艦艇一天內不可能都經過。

**根因**：`_strait_is_ship_passage` 用 ±120 字元滑動窗口（等於 240 字元），
會跨過好幾個句子。防衛省常在末段補述「なお、当該艦艇は**先般**、与那国島と
台湾との間の海域を通過している」—— 講的是**先前**的航行，卻被算成本次航跡。

**已修正**（`scraper_japan_mod.py`）：

1. 改以**句子**為判斷範圍，不用字元窗口
2. 排除 `先般`/`前回`/`過去`/`これまで` 等指向過往事例的句子
3. 加地理一致性檢查：緯度跨距 > 7 度時依**文本證據強度**取捨

第 3 點的取捨依據很重要。這些誤判多是俄羅斯艦艇，實際航跡是**對馬海峽**
（海參崴往東海），與那國才是誤判 —— 若照「保留南側」之類的幾何規則去猜，
會正好砍掉真的那個。證據不足時一律不猜，只回報衝突。

**最終結果（2026-07-25 執行三輪）：13 → 11 → 10 → 7 筆，`conflict_count: 0`。**

剩下 7 筆全部是已知的非問題：

| 同日多批艦艇（非衝突） | 2026-06-29、06-30 | 不同批艦艇，多海峽本來就正確 |

三個目標日期全部判定正確：
`2026-03-10 → 與那國`、`2026-03-18 → 對馬`、`2026-07-01 → 宮古`。

海峽標記總數 152 → 145（淨移除 7 個誤標），`艦型`/`進`/`出`/`架次`

### 三筆殘留衝突的判定結果（2026-07-25）

診斷輸出拿到原文後，三筆都能明確判定，而且**答案彼此相反** ——
任何幾何規則都會做錯其中一個：

| PDF | 當次航跡 | 應剔除 | 依據 |
|---|---|---|---|
| p20260310_01 (3/10) | 與那國 | 對馬 | `なお…３月５日…したものと同一である` |
| p20260318_02 (3/18) | 對馬 | 與那國 | `その後、１７日〜１８日…対馬海峡を北東進` |
| p20260701_01 (7/1) | 宮古 | 對馬 | `なお…６月２７日…したものと同一である` |

新增兩個判別措辭：

- `ものと同一` / `と同一である` —— 「與先前某次航行的是同一批艦艇」，
  純身分識別，講的不是本次航跡
- `なお` + 明示日期 —— 補述句回顧先前航行

### 更底層的問題：句子被換行切碎

診斷輸出同時暴露 `_split_sentences` 把 `\n` 當句子邊界的錯誤。實測片段：

```
「その後、これらの艦艇が与那国島（沖縄県）と西表島との間の海域を南西進し、太」
「（日）から６日（月）にかけて与那国島と西表島との間の海域を南西進した後、令和」
```

第一段結尾是「太」（太平洋被截斷），第二段開頭是「（日）」—— 都是 PDF
換行片段而非句子。這會把 `なお`、`ものと同一である` 跟海峽名切到不同片段，
過往指涉的判定永遠碰不到。

已改為先去除換行、只依「。」斷句。日文不用空白分詞，直接接合即可。

**接合後的副作用**：句子變長，一句裡可能同時含本次航跡與 `なお` 補述，
整句判為過往指涉會連本次航跡一起丟掉。實測 2026-07-07（大禹）與
2026-07-20（宮古）在此輪標記歸零，疑似就是這個原因。因此再在 `なお`
處切一刀，讓補述自成一段、前半的航跡得以保留。

八個測試案例全通過（三筆真實 PDF + 同句混合 + 跨句航跡 + 相鄰海峽 +
純飛機 + 先般）。
