# SurgeForecaster 3.0.0 → 3.1.0：零架次 regime 修正與前後回測

## 背景

2026 年零架次日大幅增加（2024: 20 天、2025: 22 天、2026 到 9/25 已 69 天），日均架次由約 14 降到 7.4。
3.0.0 在這個 regime 下的問題：

1. **點預測不會預測 0**：零架次期間平均每天多估 7.6 架次，比「照抄昨天」（1.65）差 4 倍。
   根因之一是 2024 年以前的資料根本沒有記錄零架次（2020–2023 目標值為 0 的比例是 0%）。
2. **機率校準不穩**：Platt 校準窗只有 180 天，零架次偏多時斜率被壓到約 0.5，
   而且每次重訓斜率不同，跨天排序被打亂（原始分類器 ROC-AUC 0.655 → 校準後 0.587）。

## 3.1.0 改了什麼

| 項目 | 3.0.0 | 3.1.0 |
|---|---|---|
| Platt 校準窗 | 180 天 | **365 天**（`CALIBRATION_WINDOW`） |
| 零架次特徵 | 只有 zr7/zr28/zr56 | 加 `zero_streak`、`days_since_active`、`last_active_val`、`zero3` |
| 零架次閘門 | 無 | 原點為 0 且近 180 天「0 之後仍為 0」比例 ≥ 50% → 點預測給 0（`ZERO_GATE_PROB`） |
| 點預測訓練權重 | 等權 | **只在零架次 regime 時**（近 180 天零架次比例 ≥ 15%）用半衰期 365 天的時間衰減，否則等權（`POINT_WEIGHT_ZERO_SHARE`） |
| 預測區間 | 以點預測為中心 | 以模型點預測為中心（閘門不縮窄區間，0 之後照樣可能反彈） |
| 風險階梯 | max(絕對下限, 倍數 × 全訓練集基準率) | 倍數改乘校準窗（365 天）的基準率，也就是機率被校準到的那個基準 |

新增 CSV 欄位：`zero_gated`（是否觸發閘門）。

## 試過但沒採用

| 想法 | 結果 |
|---|---|
| **排名警示**：原始分數在近一年前 10% → 至少 MEDIUM-HIGH | 主要回測命中 +3（95% CI −11..+16，雜訊）；保留期警示率 17% → **32%**，lift 僅 1.15；推播會出現「🟠 但機率 15%」。**已撤回** |
| **無條件時間加權**（半衰期 365） | 主要回測 MAE −0.40，但保留期 **+0.23**（型態沒變時丟掉有用的歷史）。改為有條件 |
| 「明天是否為 0」分類器（全資料／僅 2024+／時間加權） | 2026 ROC-AUC 僅 0.50–0.61，學不起來 |
| Hurdle 模型：(1−P(0)) × E[架次 \| >0] | 全期 MAE 8.12–8.17，比現行差 |
| 把 zr28 當 Platt 第二特徵 | 無增益 |
| 半衰期 90 / 180 天 | 不如 365 天 |
| 維持 180 天校準窗（其餘同 3.1.0） | 點預測完全相同；Brier 0.165（365 天為 0.162）、ROC-AUC 0.594（0.618）；警示 16 次命中 7 |

## 前後回測

方法：`scripts/analysis/backtest_predictor.walk_forward`，h=1，每 28 筆訓練資料重訓一次，embargo 8 天。
舊版用 3.0.0 的程式碼、新版用本分支，資料與切點完全相同。上線是每日重訓，絕對數字會與線上紀錄略有差異。
差值的 95% 信賴區間用**以週為單位的 block bootstrap**（2,000 次），以保留自相關。

兩個回測窗：

- **主要回測**：2024-07-01 → 2026-09-25（813 天，173 個高架次日）。參數是在這段挑的，數字偏樂觀。
- **保留期**：2022-07-07 → 2024-06-30（674 天，153 個高架次日）。挑參數時沒碰過，但幾乎沒有零架次日
  （12 天），閘門一次都沒觸發 —— 驗證的是「新版在舊型態下不會變差」，不是零架次改進本身。

## 結論與代價

**站得住的：**

- 零架次期間 MAE 減半（7.64 → 3.92），2026 全年 −0.60；主要回測整體 MAE 改善顯著（−0.17，CI 不含 0）。
- 保留期點預測持平（+0.01，CI −0.14..+0.16）：有條件加權與閘門在舊型態下都不會啟動，不會變差。
- 機率準度（Brier）兩個窗都改善，保留期顯著。

**代價 —— 請特別注意：**

- **警示幾乎消失。** 校準後機率很少超過 30% 警示線：主要回測由 88 次降到 4 次，2026 年由 6 次（命中 5）
  降到 4 次（命中 1）。舊版那 88 次在主要回測有 lift 1.66，但在保留期 113 次 lift 1.01、等同隨機 —— 不穩定。
  本版刻意不為了「有警示」去調低門檻；LINE 端的 `ladder_unreachable` 診斷會提示
  「風險等級恆為 LOW 不代表低風險」。若要恢復一定數量的警示，需要另外決定警示政策（例如固定每月警示天數），
  而那等於承認機率本身沒有區分力。
- 低估略為加重：主要回測 bias −0.67 → −1.01、pin90 +0.05（不顯著）。
- 上線窗的 6 次高架次日新版也一次都沒抓到；那些突增在現有特徵裡沒有前兆。
- 機率技能仍然很低（Brier 只比全押基準好 3–4%，保留期兩版都比基準差）。

## 重現

```bash
# 新版（本分支）
OMP_NUM_THREADS=2 python3 scripts/analysis/backtest_predictor.py --days 816 --horizons 1
# 舊版：把 3.0.0 的 pla_surge_model.py 與 scripts/analysis/backtest_predictor.py
# 取出到另一個目錄後執行同一指令
```

多個回測同時跑時請設 `OMP_NUM_THREADS`（例如 1–2），否則 HistGradientBoosting 的
執行緒互搶會慢一個數量級。
