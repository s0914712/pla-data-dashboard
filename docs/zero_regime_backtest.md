# SurgeForecaster 3.0.0 → 3.1.0：零架次 regime 修正與前後回測

## 背景

2026 年零架次日大幅增加（2024: 20 天、2025: 22 天、2026 到 9/25 已 69 天），日均架次由約 14 降到 7.4。
3.0.0 在這個 regime 下有兩個問題：

1. **點預測不會預測 0**：零架次期間平均每天多估 7 架次，比「照抄昨天」（1.65）差 4 倍。
   根因之一是 2024 年以前的資料根本沒有記錄零架次（2020–2023 目標值為 0 的比例是 0%）。
2. **機率換算把高架次機率壓到永遠不會警示**：Platt 校準窗只有 180 天，而這 180 天有 24% 是零架次日，
   配出的斜率約 0.5（原始 50% 只映成 20%），校準後幾乎不可能超過 30% 警示下限；
   而且每次重訓斜率不同，跨天排序被打亂（ROC-AUC 0.655 → 0.587）。

## 改了什麼

| 項目 | 3.0.0 | 3.1.0 |
|---|---|---|
| Platt 校準窗 | 180 天 | **365 天**（`CALIBRATION_WINDOW`） |
| 警示規則 | 校準機率 ≥ max(30%, 2×基準) | 同左，**或**原始分數在近一年樣本外分數的前 10%（`ALERT_RANK`） → 至少 MEDIUM-HIGH |
| 點預測訓練權重 | 等權 | **時間衰減，半衰期 365 天**（`POINT_HALF_LIFE`） |
| 零架次特徵 | 只有 zr7/zr28/zr56 | 加 `zero_streak`、`days_since_active`、`last_active_val`、`zero3` |
| 零架次閘門 | 無 | 原點為 0 且近 180 天「0 之後仍為 0」比例 ≥ 50% → 點預測給 0（`ZERO_GATE_PROB`） |
| 預測區間 | 以點預測為中心 | 以模型點預測為中心（閘門不縮窄區間，0 之後照樣可能反彈） |

新增 CSV 欄位：`high_event_rank`（排名百分位）、`zero_gated`（是否觸發閘門）。
`probability_review.py` 對新模型改以 `risk_level` 判定是否警示（即推播實際顯示的等級）。

## 試過但沒採用

| 想法 | 結果 |
|---|---|
| 「明天是否為 0」分類器（全資料／僅 2024+／時間加權） | 2026 ROC-AUC 僅 0.50–0.61，學不起來 |
| Hurdle 模型：(1−P(0)) × E[架次 \| >0] | 全期 MAE 8.12–8.17，比現行差 |
| 把 zr28 當 Platt 第二特徵 | 無增益 |
| 半衰期 90 / 180 天 | 全期 MAE 8.26 / 8.01，不如 365 天（7.81） |
| 風險等級分三階排名（前 5% / 10% / 20%） | 前 5% 的命中率（25%）不比 5–10%（44%）高，只設一階 |

## 前後回測

## 代價與限制

- **低估略為加重**：全期 bias −0.67 → −1.59，pin90 4.30 → 4.47（+4%），高架次日平均少估 17.2 → 17.8。
  這是閘門與時間加權把預測往 2026 的低活動水準拉的結果。
- **上線窗的 6 次高架次日新版也一次都沒抓到**：這些日子的原始分數排名只在第 5–78 百分位（沒有一天進前 20%），
  任何警示規則都救不回來 —— 那段期間的突增在現有特徵裡沒有前兆。
- **2026 年 precision 由 0.83 降到 0.50**：舊版 2026 只警示 6 次，樣本太少；
  新版警示 12 次命中 6 次。全期看 precision 與 recall 都是新版較好。
- 機率仍幾乎沒有技能（Brier 只比全押基準好 3–4%），警示應視為「相對較高」而非「很可能發生」。

## 重現

```bash
# 新版（本分支）
python3 scripts/analysis/backtest_predictor.py --days 816 --horizons 1
# 舊版：把 HEAD 的 pla_surge_model.py 與 scripts/analysis/backtest_predictor.py
# 取出到另一個目錄後執行同一指令
```

多個回測同時跑時請設 `OMP_NUM_THREADS`（例如 2），否則 HistGradientBoosting 的
執行緒互搶會慢一個數量級。
